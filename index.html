The system in six pieces

Think in layers. The model reasons; Hermes supplies continuity, procedures, tools, execution surfaces, and automation.

Model · reasoning

Provider and model produce decisions and language. Swap them without rebuilding the rest.

Tools · action

Web, browser, terminal, files, vision, code execution, delegation, cron, and more.

Skills · procedure

Reusable playbooks with exact commands, pitfalls, and verification steps.

Memory · continuity

Small curated facts about you, stable preferences, and durable environment conventions.

Profiles · boundaries

Independent agent homes with separate config, keys, memories, sessions, and skills.

Gateway · reach

Talk from Telegram or other channels; add schedules and webhooks for always-on work.

The key distinction: tools are capabilities available now; skills explain how to use capabilities well; memory carries only what should survive into future sessions.

Your first 30 minutes

Establish one clean path from request to verified result before adding more integrations.

Verify the baseline

Confirm model, provider, gateway, tools, and skills before changing configuration.

hermes doctor
hermes status --all
hermes tools list
hermes skills list

Run a real, read-only task

Start with inspection. This reveals how Hermes gathers context without risking edits.

hermes chat -q "Inspect this project. Do not edit files. Map the architecture, identify the top five risks, and propose a prioritized plan with evidence."

Practice session control

Try /help, /status, /model, /skills, /tools, /title, /retry, /undo, /stop, and /new.

Teach one durable preference

Say: “Remember that I prefer implementation answers with copyable commands, verification output, and explicit assumptions.”

The best additions for your setup

Add leverage in this order. Each layer should solve an observed problem—not merely increase the number of integrations.

Do now

Project context files

Add a focused AGENTS.md to active repos: architecture, commands, conventions, test gates, and “done” criteria. Use .hermes.md only for Hermes-specific hierarchical rules.

20 min
Do now

GitHub authentication

Connect gh so Hermes can inspect PRs, CI, issues, releases, and repository state using the bundled GitHub workflow skills. Keep write operations approval-gated.

Do now

Coding + research profiles

Create separate coder and research profiles. This prevents credentials, memories, automations, and accumulated context from becoming one undifferentiated agent.

Next

Local voice stack

Keep Edge TTS with Ava Multilingual. Add local faster-whisper for private, low-latency speech-to-text that your M5 Max can run comfortably.

30 min
Next

One reviewed MCP server

30–60 min
Next

One Telegram automation

Create a reversible one-shot briefing first. When the output is useful, make it recurring, pin its model/provider, attach only needed skills, and define a delivery target.

20 min
Later

Local model lane

Use llama-cpp with Metal for private classification, summarization, or experimentation. Benchmark quality and latency against your hosted model before routing production work locally.

1–2 hr
Later

Provider fallback + credential pools

Add a second provider only after the base setup is stable. Use explicit routing and cost boundaries instead of silently changing defaults for unattended jobs.

30 min

How to work with Hermes well

The quality jump comes from task contracts: scope, authority, evidence, completion criteria, and verification—not elaborate prompt poetry.

1 · Inspect first

Use when context is unfamiliar or the cost of a wrong edit is high.

“Inspect the repo and relevant docs first. Do not edit. Report what you found, unknowns, and the smallest safe next step.”

2 · Plan with gates

Ask for an actionable plan only when the task is genuinely multi-step.

“Create a plan with files, tests, risks, and verification. Mark assumptions. Wait only if a missing decision changes implementation materially.”

3 · Execute to proof

Require a working artifact and real output, not a description of future work.

“Implement the smallest complete change. Run tests and type checks, inspect the diff, fix failures, then report exact evidence.”

4 · Delegate by boundary

Parallelize independent questions—not tightly coupled edits to the same files.

“Delegate security, performance, and UX reviews independently. Pass each the path, diff scope, constraints, and required output. Synthesize after all three return.”

5 · Research source-first

Define source quality, date range, and output structure.

“Use current primary sources where possible. Separate facts, inference, and recommendation. Include links and note uncertainty or conflicting evidence.”

6 · Automate last

Turn a successful manual workflow into a schedule—not the other way around.

“Run this once now. If successful, propose a recurring schedule with pinned model, minimal toolsets, failure alert, and exact delivery target.”

Steer while work is running: use direct mid-turn guidance to narrow scope, add constraints, or stop a wrong path. You do not need to wait for a long task to finish before correcting direction.

07 / 10

Use the M5 Max deliberately

Your hardware removes many local constraints. It does not remove the need to bound work, isolate risk, and choose the right execution lane.

Parallel work

Three independent subagents is a strong default. Increase concurrency only when tasks do not fight over context or files.

Local services

Run browsers, databases, app servers, and analysis jobs locally without immediately moving to cloud infrastructure.

Long-running work

Use tracked background processes with completion notification; use cron for durable schedules.

Local inference

Use Metal-compatible llama.cpp experiments for privacy, latency, or cost—not merely because memory is available.

Project separation

Pair profiles with project workspaces and explicit AGENTS.md instructions.

Resource discipline

Bound commands with timeouts, stop runaway workers, and keep the laptop interactive during builds.

08 / 10

Four workflows worth keeping

These are short task contracts you can reuse and adapt without turning every request into a specification document.

Product discovery

“Research current approaches to [problem]. Prefer primary sources. Compare five options, map trade-offs, then propose an MVP architecture with data flow, tool boundaries, risks, and open questions.”

Frontend delivery

“Inspect this repo, plan the smallest complete change, implement it, run relevant tests and type checks, inspect the diff, and report files changed plus verification output.”

Agentic review

“Run independent security, performance, UX, and maintainability reviews. Deduplicate findings, rank by impact and confidence, and separate must-fix issues from optional improvements.”

Research briefing

“Create a concise weekly brief on [topic] from current sources. Include what changed, why it matters to an AI-native product engineer, links, and two experiments worth trying.”

A seven-day learning path

One focused capability per day; each day produces a real result rather than another configuration layer.

DAY 1

Tool fluency

Research, inspect a repo, edit one file, test, and control the session.

DAY 2

Project rules

Add AGENTS.md; use plan, TDD, and review skills.

DAY 3

Profiles

Separate coding and research identities, memory, and state.

DAY 4

MCP

Install one reviewed server and test its read-only path.

DAY 5

Delegation

Run a three-way review with explicit child context.

DAY 6

Remote + voice

Work through Telegram and generate an audio brief.

DAY 7

Automation

Turn one successful manual workflow into a reversible job.
